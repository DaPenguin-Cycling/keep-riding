{%- comment -%} schema.org JSON-LD. Why this exists: the pages say plainly who Anthony is, where he rides and what he has finished, but they say it only in prose. A search engine — and, more to the point now, an answer engine summarising "who is DaPenguin" or "what rides has Anthony Brown done" — has to infer all of it. This states the same facts in a form that does not need inferring. Nothing here is new information: every value is either already printed on a page or already in _config.yml / _data. If a fact stops being true on the page, change it here in the same commit. One `@graph` in one script rather than several scripts: the nodes reference each other by `@id`, so the Person that publishes the site and the Person the page is about are understood to be the same person rather than three lookalikes. Everything interpolated goes through `jsonify`, which emits the surrounding quotes and escapes what is inside them. That matters more than it looks — the site's copy is full of apostrophes and em dashes, and a bare "{{ value }}" would produce invalid JSON the first time a ride name contained a quotation mark. {%- endcomment -%} {%- assign fb = site.social.facebook | default: "" -%} {%- assign st = site.social.strava | default: "" -%} {%- if st == "" -%}{%- assign st = site.data.stats.stravaUrl | default: "" -%}{%- endif -%} {%- assign site_id = "/#website" | absolute_url -%} {%- assign person_id = "/#anthony" | absolute_url -%} {%- assign page_id = page.url | absolute_url | append: "#webpage" -%} {%- assign social = "" | split: "" -%} {%- if fb != "" %}{% assign social = social | push: fb %}{% endif -%} {%- if st != "" %}{% assign social = social | push: st %}{% endif -%}
